# Kernel modules: `require` in place of the concat

Date: 2026-10-16
Goal: the kernel compiles itself from its real source layout — 22
`selfhost/cato/**/*.cato` files wired with `(ns ...)` and `(require ...)`
— so the generated single-namespace concat (`selfhost/cato.cato`) and its
generator (`tools/concat_kernel.py`) can be deleted. Every build path
(seed gate, kernel self-build, the S4–S7 harnesses) points at a real
entry file instead of a concatenation.

Status: design, approved for planning.

## Problem

`selfhost/cato.cato` is a committed 13k-line concatenation regenerated by
`tools/concat_kernel.py` before every build and guarded by a
byte-freshness test (`kernel_bootstrap.rs::kernel_concat_is_fresh`). It is
the only distribution form of the kernel and the only thing the seed and
the kernels are pointed at. That generator/pre-concat step is pure
overhead: the language already has `(ns ...)` and `(require [... :as
alias])` (Phase 19), and the roadmap's "after the fixpoint" item is
exactly "split `selfhost/` into namespaces (kernel grows `require`
merging)".

Two facts shape the work:

1. **The kernel compiler has no `require`.** `selfhost/cato/hir/expand.cato`
   only reserves `s-ns` (66) / `s-require` (67) and their magic-table
   entries; nothing consumes them. `compile-to-ir` (`cli.cato:45`) is
   single-file: `slurp → read-all-with → expand-all → compile-build`.
   Pointing the kernel at a `require`-using entry without implementing
   `require` in Cato breaks the self-build (k1 can't compile the source
   that produced it).

2. **The seed's Phase-19 `require` cannot express the kernel's graph.**
   `expand_file` (`crates/cato-core/src/lib.rs:280`) renames a required
   file's `defn`/`extern` names to `alias__name` and rewrites only the
   *requiring* file's `alias/name` heads. A repeat require of the same
   file is skipped without registering rewrites (`lib.rs:321`), so any
   diamond — `forms` and `lower` both need `lib/ast`, etc., pervasive in
   the kernel — leaves the second requirer's refs unresolved. Types are
   never renamed (already global); only `defn`/`extern` are.

Cross-file surface today: 2468 call heads, zero duplicate
`defn`/`extern` names across the 22 files.

## Design

### 1. Seed semantics: canonical-per-file rename

Replace the parent-prefix recursion in `expand_file` with a
module-graph model:

- Resolve the graph recursively, dedup by resolved path string (insert
  before recursing, so cycles terminate), and assign each file a
  **canonical alias** — the alias it is first required with.
- Per file, in place: rename its own `defn`/`extern` names `n →
  canonical__n` (headers + every ref, via the existing `rewrite_heads`
  walk) and rewrite each `localAlias/name` ref to `canonical(child)__name`
  where `child` is the file the local alias was bound to. Type names are
  untouched.
- Merge in traversal order; drop `(ns ...)` and `(require ...)` forms.
- Validate and error (with span) on: malformed `require` spec, malformed
  `ns`, duplicate `ns` name across the graph, and a call through an unbound
  local alias.

Now each module has exactly one set of canonical definitions, so a second
requirer maps its alias onto them — diamonds resolve. Single-requirer
cases (all `examples/`, `parity::modules_agree_between_backends`) produce
identical output; only nested/multi-alias internal symbol names change,
and no test asserts those shapes.

`compile_named_with` keeps its signature; only `expand_file` and its
helpers change.

### 2. Kernel-side loader (written in Cato)

New `selfhost/cato/hir/modules.cato`, required by `cli.cato`, invoked in
`compile-to-ir` between `read-all-with` and `expand-all`. It mirrors the
seed exactly, over the kernel AST, and returns an outcome carrying the
merged forms, the threaded intern table, and the updated module state
(`OK`/`Err` variants over an ADT, as elsewhere in the kernel):

```
resolve-modules path forms tab state -> ORES{forms, tab, state | msg, span}
```

- Drop `(ns name)` (validate; record in state for uniqueness).
- For `(require [p :as a])`: child = `dirname(path) ++ "/" ++ p`; skip if
  already in the seen set (but still register the requirer's alias
  rewrites); else record it, `slurp` the child, `read-all-with` with the
  threaded `tab`, and recurse.
- Collect the child's `defn`/`extern` name sids; intern each
  `canonical__name` (`stab-get` name, `str`, `stab-find`/`stab-conj`);
  rename the child's heads and refs; register `a/name → canonical__name`
  and rewrite the requirer's own refs; append the child's forms in order.
- Helpers ported from the seed over `Ast`/`Asts`: `require-of`,
  `defn-names`, `rewrite-heads`, plus a `dirname` built from
  `split`/`join`. Errors surface as `EErr` with spans, message-for-message
  matching the seed.

State (seen files, ns names, alias→file bindings) threads as persistent
kernel structures (assoc lists / vectors), matching the codebase's
existing threading style. Because renaming interns new strings, `tab`
threads through the loader and on into `expand-all`/`compile-build`.

### 3. Source conversion (one-shot script, reviewed as a diff)

- Add `(ns cato.<path>)` to all 22 existing kernel files (and the new
  `hir/modules.cato`).
- Give each file `(require ["<relative>" :as <alias>])` for every module
  whose `defn`/`extern` names it calls directly (derived from a
  name→owner map built by scanning `defn`/`extern` heads).
- Rewrite the 2468 cross-file call heads `foo → <alias>/foo`. One
  canonical alias per module, used everywhere (e.g. `sym`, `strbuf`,
  `span`, `ast`, `alist`, `result`, `read`, `rdump`, `types`, `expand`,
  `forms`, `hexpr`, `lower`, `moveck`, `hdump`, `state`, `scalars`,
  `heap`, `adt`, `closures`, `emit`, `modules`). Type references are left
  unqualified (types are global).
- Convert the `_ref` harnesses to require-based entries, each defining its
  own `main` and requiring the modules it drives: `lib/stdlib_ref`,
  `reader/reader_ref`, `hir/hir_ref`, `emit/emit_ref`. `cli.cato` is the
  kernel entry. `_ref` files must not appear in each other's or cli's
  graph (one `main` per compilation). Fixture files (`hir/fixtures/*`,
  `reader/fixtures/*`) are untouched.

### 4. Build, test, gate rewiring; deletions

- Delete `selfhost/cato.cato` and `tools/concat_kernel.py`.
- `tools/kernel_gate.sh`: drop the concat step; seed-build, k1-build and
  k2-build all take `selfhost/cato/cli.cato`; fixpoint (`k2.ll ==
  k3.ll`), fixtures and the ALLOC metric are unchanged.
- `crates/cato-backend-interp/tests/kernel_bootstrap.rs`: delete
  `kernel_concat_is_fresh`, `generate_concat`, `CONCAT_FILES`; drive
  `selfhost/cato/cli.cato` through the interp.
- `crates/cato-backend-interp/tests/selfhost.rs`, `kernel_reader.rs`,
  `kernel_hir.rs`, `kernel_emit.rs`: delete `CONCAT_FILES` and the
  concatenation; build/run the `_ref` entry (its requires pull the rest).
- Update `ROADMAP.md` (S8/S9 text), `HANDOFF.md` quick commands, and the
  S8 spec's concat section to describe the module layout.

### 5. Path and ownership rules

- Both compilers dedup requires by the resolved path **string**. Kernel
  source must use one canonical relative spelling per module (e.g.
  `../lib/ast.cato` from `hir/`); both implement the same
  `dirname`+`join` with no normalization.
- The loader inserts a file into the seen set before recursing (cycle
  termination), same as the seed.
- `unclone.py`/`autoclone.py` keep working: they transform single files,
  `alias/name` heads are ordinary symbols, and type refs stay unqualified.
  After conversion, re-derive their type-source lists if any.

## Risks

- **Seed/kernel parity is the contract.** Both must accept/reject the same
  programs. The loader is a line-for-line port; the gate's fixpoint plus
  the fixture suite plus `examples/` are the evidence.
- **ALLOC churn will move.** The kernel self-build now parses the graph
  via `require` (more work per build). The gate's PASS criteria
  (deterministic bytes/calls, fixpoint, fixtures) are unchanged; the
  HANDOFF's absolute churn numbers are re-baselined.
- **Symbol-shape change** for nested/multi-alias requires (single prefix
  instead of re-prefixing). Externally visible only in IR symbol names;
  no test depends on them.
- **Path spelling drift** would silently double-load a module (duplicate
  defns) or miss a dedup. Mitigated by a single canonical spelling per
  module and the seed's duplicate-defn rejection.

## Verification

- `cargo build` and `cargo test` — notably
  `parity::modules_agree_between_backends`, the `kernel_*` tests,
  `selfhost::seed_builds_the_kernel_stdlib_and_both_backends_agree`.
- `./tools/kernel_gate.sh` → `GATE: PASS` (fixpoint, t1–t6, bk1/bk3 ok,
  bk2/bk4 rejected).
- `python3 -m pytest tools/tests/test_unclone.py -q` — 13/13.
- Every `examples/*.cato` keeps its exact output.

## Non-goals

- Byte-matching the seed's `--emit-ir` on the kernel source.
- General module features beyond what the seed has (no qualified
  re-export, no `:refer`, no per-symbol imports).
- The middle end / codegen improvements (unchanged scope).
